## Reihenfolge

Drei Sprints mit klaren Erfolgskriterien:

### Sprint 1 — Plan als first-class Artefakt (2 Tage)

**Tasks:** 1, 2, 3, 4

**Erfolgskriterium:** Ein `forge run --multi-agent` produziert einen
`PlanProposed`-Event mit gespeichertem Plan-Markdown im Blob-Store.
`forge replay <id>` zeigt den Plan in der Markdown-Timeline.

**Test:** Run gegen ein Mini-Repo mit MockCodingAgent, der einen
Plan-Text simuliert. forge muss ihn extrahieren + persistieren.

### Sprint 2 — Inter-Generation-Memory + Score-Modi (2 Tage)

**Tasks:** 5, 6, 11

**Erfolgskriterium:** 
- Drei-Modi-Score-Logic in scoring.py mit Tests
- Run-Context-Helper baut akkumulierte KEPT-Diffs zusammen, splice in
  Prompt der nächsten Generation
- Wenn Subagent „nichts mehr zu tun" zurückgibt, beendet der Run sich
  selbst

**Test:** PINTA-Smoke-Run mit 3 Generations: Gen 0 KEPT, Gen 1 sieht
Diff von Gen 0 im Context und schlägt entweder NÄCHSTE Verbesserung vor
oder sagt explizit „fertig". KEIN Geld für Wiederholungs-Versuche.

### Sprint 3 — Hybrid-Subagent-Lookup + Trigger-Konfig + `forge plan` (1 Tag)

**Tasks:** 7, 8, 9, 10

**Erfolgskriterium:** 
- forge findet `<project>/.forge/agents/<name>.md` zuerst, fällt zurück
  auf forge-Defaults
- project.yaml akzeptiert `agents: [...]`-Liste pro Trigger
- `forge plan <prompt>` produziert nur einen Plan, ohne Implementation

**Test:** Override eines Subagents in einem Test-Repo, verify dass
Override genutzt wird. `forge plan ...` produziert Plan-Markdown ohne
Code-Änderungen am Worktree.

## Risiken

1. **Plan-Extraktion ist heuristisch** — Claude Code's Subagent-Output
   ist Tool-Result-block, nicht klar formatiert. Wenn der Master-Claude
   den Plan in seinen finalen End-Turn-Text einbaut statt als isoliertes
   Tool-Result, müssen wir parsen.

2. **Inter-Gen-Memory könnte Token-Limits sprengen** — wenn Gen 0 einen
   großen Diff produziert + Gen 1 + Gen 2, kann der Context explodieren.
   Mitigation: Diff-Summary statt Full-Diff (z.B. nur file:line-Liste
   plus Kurzbeschreibung).

3. **Plan-Persistenz vs. Subagent-Output-Format** — Claude Code's
   `--output-format json` liefert `result`-feld als finalen Master-Text.
   Subagent-Outputs (Tool-Results) sind in `iterations` versteckt.
   Eventuell brauchen wir feinkörnigeres Parsing.

## Erfolgs-Bilanz nach Sprint 3

forge v0.3 ist „done" für M1.5, wenn:

- 200+ Tests grün, lint clean
- Spec v0.3 vollständig durch Tests gedeckt
- Ein realer PINTA-Run produziert: Plan (im Blob-Store) + Diff + PR
- `forge replay` zeigt den Plan als erste Sektion
- Inter-Gen-Memory verhindert „no_significant_change"-Wiederholungen
- Score-Logic dokumentiert die drei Modi mit echten Tests
